# 隅田川花火大会 3Dシミュレーション

Navara map engine を使った、隅田川花火大会（第49回・2026年7月25日）の
3D シミュレーションです。

実在の打ち上げ地点（第一会場＝桜橋下流〜言問橋上流、
第二会場＝駒形橋下流〜厩橋上流）から、牡丹・菊・冠・型物・十字菊・小玉を
物理シミュレーションで打ち上げます。1 周 256 秒が実際の 90 分に対応し、
19:00 の薄明かりから 20:30 の暗い空へ、番組の進行と一緒に空が暮れていきます。

時刻・雲量・雨量・風向・風速・煙の量をスライダーで動かせます。
Navara の大気散乱は太陽の位置から物理的に空の色と明るさを計算するので、
昼間は花火がほとんど見えず、20 時を過ぎると色が立ち上がります。
風速を 0 にすると煙が会場上空に滞留して後半が霞む、という
実際の大会で毎年起きることも再現できます。

観覧スポットは 7 か所。切り替えると**音の遅れ**が変わります。
光は一瞬で届きますが、音は 343 m/s しか進みません。
桜橋の上では 1.1 秒、両国橋で 4.6 秒、お台場（約 10 km）では 28.9 秒。
遠いほど高い周波数が空気に吸収されるので、低くこもった音だけが届きます。

## セットアップ

```bash
pnpm install
pnpm dev
# http://localhost:8080/ を開く
```

> `@navaramap/*` は npm に公開済みのため、テンプレートのクローンは不要です。
> `npm install` は peer dependency の解決に失敗するため **pnpm を使ってください**
> （`postprocessing@6.38.3` が `three < 0.184.0` を要求するのに対し、
> Navara は `three >= 0.183.0` を要求するため npm が衝突と判断します）。

ビルド：

```bash
pnpm build     # dist/ に出力
pnpm preview   # ビルド結果を確認
```

## 操作方法

| 操作 | 内容 |
| --- | --- |
| ダブルクリック | その地点に立つ。任意の場所から花火を見られる |
| W A S D／矢印キー | 前後左右に歩く（Shift で 3 倍速） |
| Q／E | 下がる／上がる |
| 🖱 地図を自由に動かす | 上空に引いて見下ろす姿勢になる。ドラッグで移動・ホイールでズーム |
| 左パネルの観覧スポット | 実在の観覧地点に飛ぶ（音の遅れも変わる） |
| ドラッグ | 観覧スポット選択中は、その場で見回す（位置は固定） |
| 音 | 最初のクリック・キー入力・スクロールで自動的に有効になる（ブラウザの自動再生制限のため読み込み直後には鳴らせない） |
| 時刻（JST）スライダー | **この作品の主軸。** 空の明るさと番組の頭出しを兼ねる（17:30〜20:30、30 秒刻み。全域を自由に動かせる） |
| ▶ 再生 / ⏸ 一時停止 | 時刻を自動で進める |
| 時間の進む速さ | 0.25×〜4× |
| ホイール（観覧スポット選択中） | 画角が変わる（望遠になる）。立ち位置が固定されるため前後移動ではなく双眼鏡に相当 |
| 雲量・雨量スライダー | ボリュメトリック雲と、空間を落ちてくる雨粒 |
| 風向・風速スライダー | 煙の流れる向きと速さ。星と上昇中の玉も流される |
| 煙の量スライダー | 0 にすると煙なし。風速 0 と組み合わせると煙が滞留する |
| 街の明かりスライダー | 夜景の明るさ。0 で消灯 |
| 映り込みスライダー | 隅田川の水面に映る花火の強さ |
| 水面の粗さスライダー | 小さくすると鏡のように、大きくすると波立って崩れる |
| 描画品質スライダー | 星の数を 40〜100% で調整（重いときに下げる） |
| ≡ ボタン | パネルを隠す（スクリーンショット用） |

## 実装の要点

### 花火の粒子

`InstancedSphereMeshDesc` を使っています。星（火の粉）の物理計算は素の
TypeScript で行い、毎フレーム `handle.ref.replaceAll()` で
インスタンス行列に一括反映します。1 エミッタ = 1 ドローコールです。

```
玉（Shell）
 └─ 上昇（重力 + 空気抵抗、尾を引く火の粉を毎フレーム生成）
      └─ 頂点で開花
           └─ 色ごとにエミッタを取得し、種類別のパターンで星を撒く
```

**カスタム Descriptor は書いていません。**
`replaceAll()` が用意されているため、宣言的 API の範囲だけで
数万個の粒子アニメーションが成立します。

### 光らせ方

`SelectiveBloomEffectDesc` が要です。これがないと発光する球体が並んでいるだけに見えます。

**閾値（`threshold`）の調整でいちばん往復しました。**

既定の 0 のままだと「発光しているもの全部」が滲むため、東京の道路網の
細い線までブルームの対象になり、街全体が白いシートに潰れました。
そこで 0.5 まで上げたところ、今度は**道路が完全に見えなくなりました**。

理由は、夜は光源がないため発光物が色パス（attachment 0）でほぼ真っ黒で、
明るさが**ブルームからしか来ていない**ことです。
`emissiveIntensity` は選択的エフェクト用のバッファに書かれるだけで、
色パスを明るくはしません。閾値を下回った瞬間、出口が両方閉じます。

最終的に 0.22 に置いています。道路（発光 0.52）が細く滲み、
花火（発光 2.2〜3.2）が大きく滲む境目です。
あわせて夜の環境光を 0.85 まで上げ、ブルームに入らないものも
輪郭が見えるようにしています。
`radius` も 0.62 では光が広がりすぎたので 0.32 に、
`resolutionScale` は 0.5 だと滲みが四角いブロック状に見えたので 0.75 にしています。

発光値は「ブルームの閾値を超えるか」で意味が変わるため、
要素ごとに意図して振り分けています。

| 要素 | 発光値 | 滲むか |
| --- | --- | --- |
| 花火（開花直後） | 2.2〜3.2 | ○（大きく滲む） |
| 打ち上げの火の粉 | 1.4 | ○ |
| 歩行者の矢印 | 1.4 | ○ |
| 交通規制の線 | 0.95 | ○ |
| 道路（強さ 45%） | 0.52 | ○（細く滲む） |
| 煙 | 0.18 | ×（滲まない） |

煙だけを閾値の下に置いています。煙が滲むと画面全体が白い霞に覆われるためです。

- エミッタ単位で `emissiveColor` に玉の色を入れ、`effectIds` に bloom の ID を渡す
- 開花直後がもっとも明るく、`emissiveIntensity` を指数減衰させる
- 星ごとに半径を縮め、瞬き（twinkle）を掛ける

### 玉の種類

実際の花火の分類に合わせて、物理パラメータで作り分けています（`src/fireworks.ts` の `KIND_PROFILES`）。

| 種類 | 表現 |
| --- | --- |
| 牡丹 | 尾を引かず、球状にぱっと開いて速く消える（空気抵抗を大きく） |
| 菊 | 星が尾を引きながら開く（寿命を長く、抵抗を小さく） |
| 冠・しだれ柳 | ゆっくり広がり、重力で長く垂れ下がる |
| 型物（輪） | 1 枚の平面上に等間隔で開く |
| 十字菊 | 開花の途中で星が 4 方向に分裂する |
| 小玉 | スターマイン・連発用 |

多重芯（芯入り）は、同じ開花点に半径の違う層を色を変えて重ねて表現しています。

### 発数の設計

1 周 256 秒（4.3 分）で約 900 発打ち上がります。毎秒 3.5 発です。
実際の隅田川花火大会は 90 分で約 20,000 発、つまり毎秒 3.7 発なので、
密度としてはほぼ実物どおりになっています。

エミッタは 96 本のプールを使い回しています。同時使用のピークは 57 本で、
取りこぼしは発生しません（`KIND_PROFILES` と番組密度から数値検証済み）。

### 時刻の進行

**時刻スライダーが唯一の時間軸です。** 当初は「番組シークバー」と
「時刻スライダー」を別々に持っていましたが、両方が時間を動かすため
操作が競合していました。番組シークバーを廃止し、時刻に一本化しています。

時刻を動かすと、空の明るさが変わると同時に番組の頭出しにもなります。
番組 256 秒が 19:00〜20:30 の 90 分に対応するので、
空の時間 1 分が実時間 2.84 秒で流れます。

起動直後は 17:30 の薄暮から始まります。19:00 の打ち上げ開始までは
等速だと 4 分以上待つことになるので、**空だけを 8 倍で早送り**します
（実時間で約 32 秒）。19:00 に入ると等速に戻り、打ち上げが始まります。
20:30 の打ち上げ終了で 17:30 に戻り、繰り返します。1 周は約 4.8 分です
（薄暮の早送り 32 秒 ＋ 打ち上げ 256 秒）。

**時刻は一方向にだけ進みます。** 当初は番組の進行から時刻を逆算していたため、
20:30 を超えると番組がループして時刻が 19:00 台へ引き戻され、
**スライダーを 20:30 より先へ動かせませんでした**。
時刻を主、番組を従にすることで解消しています。

場面の切り替わりも実際のタイムテーブルに合わせています。

| 番組内 | 時刻 | 場面 |
| --- | --- | --- |
| 0s | 19:00 | オープニング（第一会場のみ） |
| 46s | 19:16 | 間を詰めていく |
| 85s | 19:30 | **第二会場 打ち上げ開始** |
| 135s | 19:47 | 本編（芯入り・型物） |
| 185s | 20:05 | スターマイン |
| 220s | 20:17 | フィナーレ |
| 250s | 20:28 | 余韻 |

東京の 2026 年 7 月 25 日の日没は 18:52 なので、19:00 の開始時点では
まだ薄明かりが残っていて花火の色が浅く見えます。
20:00 を過ぎると空が沈んで色が立ち上がります。
当日の「待っているうちに暗くなる」感覚がそのまま出ます。

### 視点ごとの画角

スカイツリー天望デッキからは、2 つの会場が**方位で 88 度離れて**います
（第一会場が 322.6 度、第二会場が 256.5 度）。既定の垂直画角 60 度では
片方しか入らないため、この視点だけ画角を 75 度に広げ、
方位を打ち上げ区間の端まで含めた範囲の中央（294 度）に向けています。

`Viewpoint` に `heading` と `fov` の上書きを持たせているので、
視点ごとに構図を作れます。縦横比 4:3 以上なら両会場が収まることを検算済みです。

### 操作系で詰まった点

いちばん時間を取られたのはカメラ操作でした。2 つ問題がありました。

**ホイールが効かない。** `cameraFreeLook(true)` はカメラと注視点の距離が
0 になるため、Navara の仕様でホイールのズームが無効になります。
観覧スポットに立っている状態では「前に進む」より「レンズで寄る」方が
体験として正しいので、ホイールを画角（`view.camera.fov`、12〜75 度）に
割り当て直しました。

**マウスで地点を移動できない。** Navara の標準操作は
「左ドラッグ = 地球を回す（spin）／右ドラッグ = 傾ける（tilt）／
ホイール = ズーム」で、**地点をずらす pan の割り当てがありません**
（`CameraControlUpdateEvent` に `enableSpin` / `enableTilt` / `enableZoom`
はあるが pan に相当するものがない）。上空からなら回転が実質 pan として
働きますが、地表付近では視界が大きく振れるだけで移動になりません。

そこで移動手段を 3 つ足しました。

1. **ダブルクリックでその地点に立つ** — `pickTerrainPosition()` で
   ECEF 座標を拾い、`vector3ToGeodetic()` で緯度経度に戻して
   目線の高さ 1.6 m に `flyTo` する。非エンジニアにも直感的で、
   「任意の位置から見る」にはこれが一番速い
2. **WASD / 矢印キーで歩く** — `view.moveCamera(CameraDirection.Forward, m)`。
   移動量は高度に比例させて、上空では速く地表では遅くなるようにした
3. **自由視点は上空から始める** — 見下ろす姿勢で入れば
   ドラッグが素直に「地図を動かす」ように働く

### 打ち上げ位置

打ち上げ筒は台船の上に川に沿って一列に並びます。
そのため会場は「点」ではなく **2 つの橋を結ぶ線分**として定義しています
（第一会場＝桜橋〜言問橋の 564 m、第二会場＝駒形橋〜厩橋の 388 m）。
毎発この線分上の 1 点を選び、直交方向に ±20 m ほどばらします。

当初は「中心座標＋方位角＋幅」で近似していましたが、
方位角が川筋とずれて**陸上から花火が打ち上がる**という不具合になりました。
線分で持てば川からはみ出しません。

座標は国土地理院の地名検索 API（`https://msearch.gsi.go.jp/address-search/`）から
取得した実測値をハードコードしています（実行時に叩いてはいません）。

| 地点 | 経度 | 緯度 |
| --- | --- | --- |
| 桜橋 | 139.806508 | 35.718091 |
| 言問橋 | 139.802390 | 35.714274 |
| 駒形橋 | 139.796243 | 35.708205 |
| 厩橋 | 139.794809 | 35.704907 |
| 蔵前橋 | 139.792391 | 35.700954 |
| 両国橋 | 139.787938 | 35.694021 |

### 夜景

最初は PLATEAU の建物 1 棟ずつに `emissiveIntensity` を与えて光らせました。
これは失敗でした。**発光するブロックが並んでいるように見えるだけ**で、
実際の東京の夜景になりません。スカイツリーから見下ろした実景は、
無数の小さな光点が敷き詰まった絨毯のように見えます。

そこで方式を変え、`src/citylights.ts` で街の範囲に細かい光点を
30,000 個ばらまいています（範囲 4.6 km 四方、密度 約 1,450 個/km²）。

- 光点は静的。毎フレーム更新しないので 1 ドローコールで済む
  （4×3 セグメントの球なので約 240k 三角形）
- **川の上には置かない**（中心線から 78 m 以内を除外）。
  水面が暗いままだから花火の映り込みが映える
- **橋の上には光を一列に並べる**。実景でも橋は明るい線として見える
- 色はナトリウム灯・電球色・白色・昼白色を混ぜる。単色だと嘘っぽい
- 高さは 72% が地表付近（2〜12 m）、5% が高層（45〜150 m）。
  見下ろしたときの奥行きになる
- Bloom に渡しているので、遠くから見ると光がにじんで街の光になる

建物自体は光らせず、暗いシルエットのままにしています。

光点の大きさは**カメラ高度に追随**させています。固定サイズにすると
遠くからは点が小さすぎて街が消え、近くでは浮いた球に見えてしまうため、
見かけの大きさがおよそ一定になるよう 0.4 秒ごとに倍率を調整しています
（高度 350 m のスカイツリー天望デッキで基準の約 1.9 倍）。

昼夜の判定は時刻の決め打ちではなく、Navara が計算した
**太陽の向き**（`view.atmosphere.sunDirection`）と地表法線の内積から
太陽高度を出し、市民薄明（-6 度）から +2 度のあいだで
夜景をなめらかに立ち上げています。日没直後にいきなり点灯しません。

### 水面への映り込み

Navara の水面表現は**ポリゴンのマテリアル側**にあります
（`polygon.water = true` / `waterScaleNormal` / `waterSpeed` /
`reflectivity` / `roughness`）。地形レイヤーには水面のパラメータが
ないため、隅田川の形をしたポリゴンを 1 枚敷いて水面にし、
`SSREffectDesc`（スクリーンスペース反射）と組み合わせています。

川の形は `src/river.ts` で、橋の中心を結んだ中心線を左右 55 m ずつ
オフセットして生成しています（幅 110 m・全長 3.71 km）。

実際の隅田川は浅草付近で 150〜200 m 幅がありますが、
岸にはみ出して建物や道路が光ると台無しなので狭めに取っています。
また当初は白鬚橋（桜橋の 1.1 km 上流）まで含めていましたが、
その区間は川が 30 度曲がっているため直線で結ぶとポリゴンが
隅田公園の上に乗りました。中心線は桜橋〜両国橋に絞り、
両端は接線方向に 260 m だけ延長しています。
この構成での曲がり角の食い込みは最大 6.7 m で、幅 55 m に対して余裕があります。

SSR はスクリーンスペース方式なので、**花火と川面が同じ画面に
入っているときだけ効きます**。真上を見上げて川が画面外にあるときは映りません。
これは手法の性質上の制約です。

### 雨

`RainMeshDesc` を使い、**空間を落ちてくる粒**として描いています。
`followCamera: true` にするとカメラの周囲に一定の体積の雨を保ち続けるので、
どこへ動いても雨の中にいるように見えます。

レンズに付く水滴（`RainDropEffectDesc`）は使っていません。
河川敷に立って見上げている設定なので、カメラのレンズという前提が合いません。

雨量スライダーは粒の数だけでなく、太さ・長さ・落下速度・濃さを
まとめて動かします。数だけ増やすと「細い線が増える」だけで、
雨の強さとして読めないためです。

| 雨量 | 粒数 | 落下速度 | 太さ | 長さ | 不透明度 |
| --- | --- | --- | --- | --- | --- |
| 10%（小雨） | 1,400 | 24 | 0.018 | 0.67 | 0.19 |
| 50%（本降り） | 7,000 | 34 | 0.033 | 1.35 | 0.33 |
| 100%（激しい雨） | 14,000 | 46 | 0.050 | 2.20 | 0.50 |

`alphaMax` / `alphaMin`（光が当たる側と陰になる側のアルファ）に差をつけて、
粒に立体感を出しています。`baseFov: 60` を入れているのは、
これがないと望遠（画角 12 度）にしたときに雨粒が巨大化するためです。

**風で雨が傾きます。** `RainMeshDesc` に風のパラメータはないので、
落下速度と風速の比から傾き角を出し、メッシュ自体を風下へ倒しています
（風速 5 m/s で 8.4 度、12 m/s で 19.4 度）。

### 煙と風

`src/smoke.ts` に独立した粒子系を持っています。花火の見え方を左右する
いちばん現実的な要素です。実際の大会でも「今年は煙で見えなかった」は
毎年言われます。

- 開花点と筒口から灰色の粒を発生させ、時間とともに**膨張**させる
- 粒は数フレームで気流に乗る（自分の初速が指数的に風速へ漸近する）
- 寿命は 14〜26 秒。風速 0 だとこれが会場上空に滞留して後半が霞む

不透明度はマテリアル共有で粒ごとに変えられないため、
「薄れ」は**インスタンス色を夜空の色へ補間**して表現しています。
夜のシーンなので、これが自然に「煙が溶けていく」ように見えます。

煙は発光しないので `effectIds` を渡さず、Bloom の対象から外しています。

### 音の遅延

`src/audio.ts` で Web Audio API を直接叩いています。

1. 開花時にカメラ（`view.camera.positionECEF`）から開花点までの距離を測る
2. `距離 / 343` 秒後に発音を予約する
3. 距離が遠いほどローパスのカットオフを下げる（`5200 * exp(-距離 / 1600)` Hz）

3 番目が距離感の正体です。遠い花火の音が低く感じるのは、
高い周波数が空気に吸収されて先に失われるためです。
小割（パチパチ）は高域なので、2.6 km より遠い視点では鳴らしていません。

打ち上げ音は当初、正弦波を上昇スイープさせていましたが、
それは花火ではなく**サイレンの音**でした。実際に聞こえるのは
筒の発射音「ドン」（低い衝撃音）と、上昇中のかすかな「シュー」
（無音程のノイズ）の 2 つで、どちらも音程を持ちません。
純音を使うのをやめてノイズ主体に作り直しています。

### 座標系

`eastNorthUpToFixedFrame()` で隅田川上に ENU 接平面フレームを張り、
メッシュの `matrixWorld` に渡しています。これにより花火の位置を
「東 x / 北 y / 上 z（メートル）」で書けるようになり、
ECEF を直接扱う必要がなくなります。

**標高の扱いに注意点があります。** 東京では標高（T.P.）と楕円体高が
約 37 m ずれています。高度をハードコードすると視点が地面に埋まるため、
`observeTerrainHeightAt()` で地形の実際の高さを取得し、
「地面の高さ + 目線の高さ」でカメラを配置しています。

## 既知の課題

- PLATEAU の 3D Tiles と地形の高さが数十メートルずれる場合があります
  （データセット側の鉛直基準の問題）。ずれる場合は
  `main.ts` の建物レイヤーに高さオフセットを与える必要があります。
- 粒子数が多い場面ではフレームレートが落ちます。左パネルの
  **描画品質**スライダーで星の数を 40〜100% に調整できます
  （100% でピーク約 22,000 個）。
- 地面に貼り付けた道路の線が、手前の煙より前に描かれることがあります。
  半透明の線だと煙を暗くしてしまうため、ほぼ不透明の細い線にして緩和しています。
- 煙は互いに影を落としません（自己遮蔽なし）。
  厚みのある煙の表現には `CloudsEffectDesc` 側の仕組みが必要です。
